== Objective

Join all four results to six fresh receipts and inspect relevant nonempty chains.

== Learner actions

. For each returned receipt, locate an entry with the same ID, type, hash, position and write time. Match entry content to session, request, correlation, classification, decision, reason, policy/rules digests and accountable role.
. Confirm the entry ID is absent from the baseline; its position is after that type’s baseline tip and its scenario write time is after the request. Another session, stale receipt or missing phase fails the checkpoint.
. Match every receipt to its simulated proof result. Require literal `true`, not a truthy string.
. Inspect five type chains: each simulated `chain_valid` is true, each `entries_checked` is nonzero, and coverage includes the learner positions. The completion chain includes both allowed completions. Empty chains cannot pass even when `all_valid` says true.
. Inspect the sensitive completion’s `previous_hash`: it equals the general completion’s `entry_hash` in the same type chain. Correlation joins different types; it does not turn them into one global chain.
. Copy hashes, checked counts, covered positions and scenario verification times into the worksheet. `verified_at` remains null because no runtime verifier ran.

== Validator boundary

From a local repository checkout, the following command checks fixture shape, relationships and the pinned fixture-file digest without contacting a service:

[source,bash]
----
node content-101/tools/rehearsal-check.mjs
----

It reports `REHEARSAL_VALID` and always `live_completion: false`. An invalid bundle exits nonzero. `--live` is refused, even for valid fixtures.
The fixture’s hashes and verification responses are illustrative. This checker does not recompute the ledger’s canonical hash or execute its receipt verifier. The file digest detects changes to the shipped teaching bundle, not ledger authenticity.

*Blocked live procedure:* use the session-authorized read-only proxy to retrieve exact correlated entries and hashes, then run the actual ledger verifier.
Internal source routes include `GET /api/entries?correlation_id=<id>`, `GET /api/entries/by-hash?hash=<hash>&type=<type>`, `GET /api/receipts/verify?hash=<hash>&type=<type>` and `GET /api/verify/<entry_type>`.
These are source routes, not claims that the current demo proxy exposes them safely.
Poll within a qualified bounded timeout; missing evidence fails. Never write to the learner ledger to test tampering.

== Learner checkpoint

*Pass when:* all six references match and you can identify why stale, wrong-session, empty or truncated chains fail. A valid live chain would establish integrity under its verifier’s rules, not truth, completeness, authenticated writer identity or hardware isolation. No signed-commit claim is made.
