= Sovereign AI 101 — Verify Local Inference Governance

include::partial$status.adoc[]

Can we demonstrate local inference whose permission and evidence remain inspectable?
Use this 36-minute journey to rehearse how to answer that question from four requests.
The title is a topic, not a sovereignty outcome.

== The bounded claim

After a separately qualified live run, the claim would be: “For these requests, the configured rules and policy controlled access to a locally served Granite model, and the learner inspected the resulting evidence.”
This package does not establish that claim. Its examples teach general allow, sensitive allow, injection deny and policy-unavailable abstain.

== What runs where

The source-derived path is browser → demo API `POST /api/route` → deterministic GCL prompt adapter `/v1/chat/completions` → OPA `/v1/data/sovereign/data_residency/allow` and ledger REST gateway → local OVMS `/v3/chat/completions`.
The ledger gateway bridges REST to gRPC and per-type chains backed by PostgreSQL.
Edge TLS does not establish encryption on internal HTTP or database connections.
Granite generates text after authorization in the proposed contract; it does not approve policy or run tools.

== Scope and release boundary

Exclude TDX/attestation, training, synthetic benchmarks, performance comparisons, legal compliance, unsupported sovereignty and certification claims. This package adds no AgnosticV provisioning.
The source review reports fail-open policy handling, best-effort ledger writes, missing public correlation, model metadata conflicts and unresolved local deployment readiness.
Every G01–G10 gate must pass in a current disposable environment before live delivery; a content build is not that qualification.
