# Governed inference contract v1.0

`governed-inference.ts` is the shared, versioned contract. `runtime.node-test.ts` exercises the boundary using Node's native test runner, independently of the presentation's Vitest suite. No presentation code or source-lab service is required.

Run `npm run test:server`, `npm run typecheck:server`, and `npm run dev:server` (Node 22). The default listener is `127.0.0.1:8787`; `PORT` changes the port. `SOVEREIGN_SOURCE=LIVE` or `OFFLINE` returns offline readiness and abstentions, with zero model calls. No OPA, OVMS, OpenShift, CPU placement, live ledger, or live qualification is implemented. The service does not connect to an alternate model.

## Session and HTTP use

1. `POST /api/sessions`, with an empty body, returns a server-generated session ID, bearer token, start/expiry times and an empty baseline. Tokens are transient credentials: keep them in memory, never in receipts or worksheet exports. The service stores only their hashes. This is an unauthenticated **local rehearsal session issuer**, not production identity or tenant admission.
2. Send `Authorization: Bearer <session_token>` for all remaining API endpoints. POST/PUT bodies require `Content-Type: application/json`.
3. `POST /api/route` accepts only `{ "contract_version": "1.0", "request_id": "general-1", "prompt": "What is the general framework for AI governance?", "max_tokens": 100 }`. Request IDs have 1–64 ASCII letters, digits, underscores or hyphens, starting with a letter/digit. The session and correlation IDs are server-owned. The max is 2,000 Unicode code points, 100 output tokens and 12 KiB HTTP body. The local template uses whitespace units for the rehearsal token cap; it makes no tokenizer claim. Omitted `max_tokens` normalizes to 100 for retries.
4. `PUT /api/session/fault` with `{ "fault": "policy_unavailable" }` makes that session encounter the rehearsal policy failure; `{ "fault": "none" }` restores it. Submit a **new** request ID to run a new experiment. An identical retry retains its original result, timestamp and receipts, including failures. Different content under the same ID returns 409. Fault state is captured by the first execution; retry does not re-execute it.
5. `GET /api/ledger?request_id=...&correlation_id=...` returns only acknowledged receipts from that request. `GET /api/receipts` uses the same selectors plus `hash` and `type` for an exact read. Neither endpoint accepts writes.
6. `GET /api/ledger/verify` uses the request/correlation selectors and verifies all relevant session-local type chains, including predecessors. `GET /api/receipts/verify` additionally requires `hash` and `type`. A 200 verification response must still contain literal `all_valid: true`, nonempty chains and exact matched IDs to pass. Empty or incomplete evidence returns `all_valid: false`; wrong-session/unknown selectors return 404.
7. `DELETE /api/session` invalidates the token, aborts in-flight work and drops this session's in-memory receipts, retry results and faults. Expiry does the same on subsequent access, and active requests are bounded by session expiry. This does not certify platform teardown or forensic erasure. Restart clears all ephemeral sessions. Retry guarantees last only for the session lifetime.

`GET /healthz` reports process health; `GET /readyz` reports only rehearsal availability (503 for requested LIVE/OFFLINE). Route responses use 200 for evidenced allow, 403 for deny, 503 for abstain, 422 for invalid input, 409 for conflicting ID reuse, 401 for absent/expired credentials, 413 for oversized bodies and 415 for wrong media type. Responses are JSON with `Cache-Control: no-store`; unknown paths return JSON 404. No CORS is enabled. Use a same-origin development proxy for browser integration.

## Evidence and authority

General and sensitive fixtures produce one deterministic local template response after acknowledged decision and completion receipts. Injection or explicit policy false produces denial and no dispatch. Unknown policy/rules or a failed decision acknowledgment produces abstention and no dispatch. A known denial remains enforced on receipt failure. Model failure or missing completion acknowledgment withholds text, retains the decision receipt, and reports failed/unknown execution with a dispatch count of one. Cancellation never authorizes dispatch; cancellation after dispatch reports unknown execution and withholds text. Each phase checks cancellation. The whole route is bounded to three seconds, rehearsal dependency faults to 500 ms, and HTTP input handling to four seconds.

Receipts include only minimized structured metadata and hashes: no raw prompts, generated text, credentials, destination selected by the caller, or diagnostic exception strings. Classification is limited pattern matching, not comprehensive injection protection. Model output has `text-only-no-actions` authority; a human reviewer decides the next action.

Rehearsal chains are isolated per session and event type and are unsigned. Hash encoding ports `ARE_LEDGER_ENTRY_HASH_V2` from the inspected source's `src/crypto/mod.rs`: length-prefixed UTF-8 fields include canonical content bytes, identity, correlation, timestamp, position and predecessor. This contract defines sorted-key JSON content serialization. No compatibility with a live ledger's proof endpoint is asserted without integration qualification. Verification rejects missing/truncated chains, altered content/hash/predecessor, cross-session/source evidence and pre-session timestamps. It does not establish event truth, actor identity, comprehensive recording, legal compliance or live model placement.

`RuntimeOptions` fault modes are test-only constructor settings, not public dependency configuration or outbound URLs. They cover policy timeout/connection/non-2xx/malformed/missing/nonboolean results; ledger timeout/connection/non-2xx/invalid/lost acknowledgment; completion acknowledgment failure; and model failure/timeout. Limits are 100 sessions and 100 requests per session to bound in-memory state.
